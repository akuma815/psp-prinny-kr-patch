## POC-FONT-VIS-001 — 본문 한글 글리프 가시성

- 상태: PASS — PPSSPP 실제 화면에서 `プ`→`가` 표시 확인
- 기준선: `ULJS00150` version `1.01`, 원본 `font.txp` SHA-256 `b8f7301307da33a8ef606b55d831bba1b67e4eafa1447084ab4e649d1df6c2d9`
- 발동 위험: 정적 분석으로 본문 폰트 소비자는 확인했지만 한글 픽셀이 실제 저장·적재·캐시·화면 경로를 통과한 증거가 없다.
- 가설: 기존 CP932 맵과 20×14·4bpp 캐시 경로를 유지하고 글리프 셀 하나만 바꾸면 본문 대화창에서 한글을 표시할 수 있다.
- 대상: 본문에서 실제 사용하는 `プ`(CP932 `8376`, dense index 533, glyph 371)를 임시로 `가`로 교체한다. 이 대상은 확정된 본문 렌더러를 통과하며 다른 맵 엔트리나 텍스트를 바꾸지 않는다.

### 입력과 Expected Write

- 글꼴: `../../Font/HancomMalangMalang-Regular.ttf`
- 글꼴 SHA-256: `f6682e2027b1a382d3e01546f7a7115cb26cc1245ded6b839686a069abc743b0`
- 프로파일: 13px, 가로 1.4배, 20×14 중앙 배치, 원본 팔레트 0~8, low nibble first
- 전체 글자 설정 감사: modern Hangul 11,172자, 최대 17×14, 셀 초과 0
- 허용 쓰기: `font.txp` `0xCB34..0xCBBF` 140바이트
- 실제 쓰기: 허용 셀 내부 79바이트

### 사전 판정 기준

- 통과: PPSSPP의 확인된 본문 대화 경로에서 `プ` 대신 판독 가능한 `가`가 보이고, 인접 글리프가 정상이며 대화창 이탈·재진입 뒤에도 크래시나 캐시 잔상이 없다.
- 실패: `プ`가 그대로 보이거나 다른 글리프가 바뀌거나, 픽셀이 깨지거나, 크래시·캐시 손상이 발생한다.
- 불명확: 관찰 화면이 확인된 본문 렌더러의 `プ`를 실제로 표시하지 않는다.

### 현재 결과

TTF cmap의 modern Hangul 11,172자 수록과 전 범위 설정 경계, `가` 래스터화, 4bpp 패킹, 동일 크기 `font.txp`와 단일 Expected Write 검증은 통과했다. 이어 원본 해시와 엔트리 경계를 고정한 `start.dat` 주입도 통과했으며, 출력 SHA-256은 `bf60516243264da1d221859e1315cbf8d5b2cf02c6bacbc0b209779e0c1c526e`다. LZS 압축기는 원본 스트림을 바이트 동일하게 재현했고 PoC `start.lzs`를 자기 왕복했다. PoC LZS는 3,630,811바이트, SHA-256 `85431dca1d66ecca728fdc41522fc6b7b397201ccd27b657dcb2cb9dcb36fd2a`다.

PoC LZS는 원본 `SYSTEM.DAT`의 333바이트 여유 영역 안에 고정 오프셋으로 삽입됐다. 다른 6개 항목과 전체 크기를 보존한 출력 SHA-256은 `41c9fbb6049e74fb28d1f8e429146a053bfd2e5ffa86f8b17a3b52c000cf9892`이며, 삽입 LZS 재추출·해제 결과도 PoC `start.dat`와 일치한다.
