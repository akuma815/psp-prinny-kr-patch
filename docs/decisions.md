# 설계·조사 결정 기록

## DEC-132 — 문장부호 앞뒤에 각각 2px 여백 적용

- 한글 9px·공백 6px 적용 뒤에도 `!`, `?`, `,`, 말줄임표의 `.`가 앞 글자에 붙는 현상을 실제 화면에서 확인했다.
- 전체 ASCII 폭을 다시 늘리면 영문·숫자·공백까지 영향을 받으므로, 렌더러가 글리프를 선택하기 직전에 `!`, `?`, `,`와 마침표의 내부 CP932 표현 `0x8144`만 판별한다.
- 대상 문장부호는 그리기 전에 X 좌표를 2px 전진시키고 저장된 글리프 전진 폭에도 2px를 더한다. 따라서 앞 글자와 문장부호, 문장부호와 다음 글자 사이를 모두 확보하며 한글·공백 전진 폭은 유지한다.
- v3 ISO SHA-256은 `98637963c8a6a249e9b67ab74920a5c5818f3602af8eb7a6cb7646983e33d844`이며 100 tests와 PPSSPP Headless 8초 부팅을 통과했다. 실제 화면 승인 전에는 시험값으로 유지한다.

## DEC-131 — 테스트 ISO는 최신 1개만 보존

- `work`의 확정·최종 ISO는 보존하되, `production`, `builds`, `diagnostics` 아래의 중간 시험 ISO는 새 시험판의 생성과 기본 자동 검증이 성공한 뒤 이전 파일을 삭제한다.
- 빌드가 실패했거나 자동 검증을 통과하지 못한 경우에는 직전 정상 테스트 ISO를 삭제하지 않는다.
- 2026-07-22 정리 결과 이전 시험 ISO 총 23개를 삭제했고, v3 생성·자동 검증 뒤 v2도 삭제했다. 현재 `Prinny_ULJS00150_KR_Demo00_Title_Final.iso`와 최신 `Prinny_ULJS00150_KR_TwoLine_TypewriterFix_v3_Punctuation2px_Test_20260722.iso`만 `work`에 남겼다. 삭제된 시험판의 해시·판정·보고서는 재현과 회귀 추적을 위해 문서에 유지한다.
- 이후 새 테스트 빌드 절차의 마지막 단계는 최신 파일 존재·크기·해시 확인, 자동 검증 완료, 이전 테스트 ISO 삭제, 문서 갱신 순서로 고정한다.

## DEC-130 — 혼합 CP932 대사 타자 효과는 완전한 문자 단위로 공개

- `demo00/081A`의 저장 바이트에는 ASCII 쉼표와 공백이 정상 존재했다. 화면의 쉼표 누락과 출력 중 임시 한자·깨진 글자는 데이터 손상이 아니라 `0x088653A0..0x088653FC`의 `strlen/2`, `count*2` 가정 때문에 1바이트 ASCII가 섞인 문자열이 한글 2바이트 코드 중간에서 잘리는 현상이다.
- `0x088D0DCC`의 확인된 0 패딩 코드 동굴에 CP932 논리 문자 수 계산기와 완전 문자 prefix 복사기를 둔다. 원래 복사 뒤 `count*2` 위치에 다시 NUL을 쓰던 `0x088653FC`는 새 복사기가 직접 종료하므로 NOP 처리한다.
- 새 후보는 자간 시험값 공백 6px·일반 2바이트 9px도 포함한다. `Prinny_ULJS00150_KR_TwoLine_TypewriterFix_Test_20260722.iso`의 SHA-256은 `2de74b48da4f237ba7261f1a7c96b242c3a4f267018dcf50d89bcbb8cff47766`이며 97 tests와 PPSSPP Headless 8초 부팅을 통과했다.
- v1 실기에서는 폭 축소는 PASS였지만 임시 이상 문자는 FAIL이었다. 렌더러 `0x08899948..0x08899968`이 ASCII 영문자·숫자 외 문장부호를 2바이트 경로로 보내는 별도 결함을 확인했다.
- v2는 `byte < 0x80`을 모두 단일 바이트로 분류하고 각 0x29바이트 줄 버퍼를 prefix 복사 전에 초기화한다. ISO SHA-256은 `99e80a71f088753ec9f255bd852e45a1f99e534ba8896be03901aef01bba5871`이며 97 tests와 Headless 8초 부팅을 통과했다.
- 런타임 게이트는 쉼표, 출력 도중 깨진 문자 부재, 완성 전후 문자열 동일성, 실제 간격이다. 화면 승인 전 생산판으로 승격하지 않는다.

## DEC-129 — ASCII 공백 단독 축소 기각, 한글 자간 9px 시험

- 본문 렌더러 `0x08899698`은 일반 2바이트 글리프와 ASCII 공백을 모두 13px씩 전진시킨다. 최초 후보는 공백 분기 `0x08899760`만 6px로 바꿨으나, 사용자 화면에서 공백이 없는 `에트나`, `기한은` 내부도 넓게 출력되어 원인 판정이 불충분했음이 확인됐다.
- `Prinny_ULJS00150_KR_TwoLine_Space6_Test_20260722.iso`는 자동 검사에는 통과했지만 시각 게이트에서 기각한다. 이 결과는 자동 부팅 검사가 조판을 증명하지 않는 사례로 보존한다.
- 새 시험 후보는 `0x08899760`의 ASCII 공백을 6px로 두고, `0x088997C0`의 일반 2바이트 기본 전진 폭을 `13→9px`로 바꾼다. `BOOT.BIN`과 PPSSPP 실행 경로인 `EBOOT.BIN`에서 파일 오프셋 `0x957B4`, `0x95814`의 즉시값만 변경한다.
- 새 후보 `Prinny_ULJS00150_KR_TwoLine_Tracking9_Test_20260722.iso`의 SHA-256은 `ebbb3698a952c0f92f3fe6816aaec32dfe7d041733876219861cf2ad9a2f25bd`다. 전 테스트 95건과 PPSSPP Headless 8초 부팅을 통과했다.
- 현재 9px 변경은 일본어를 포함한 일반 2바이트 경로 전체에 적용되는 시각 시험이다. 적정 폭이 승인되면 CP932 사용자 정의 한글 리드 바이트 `F0–F9`에서만 폭을 바꾸는 조건부 훅으로 전환한다.
- 사용자 화면에서 이 후보는 간격 개선이 확인되지 않았고 쉼표 누락·출력 중 임시 깨진 문자가 관찰되어 시각 게이트 FAIL로 기각한다. 간격 값은 DEC-130의 타자 효과 수정 후보에서 다시 검증한다.

## DEC-126 — 통합 테스트 ISO는 BOOT와 평문 EBOOT를 함께 패치

- PPSSPP 부팅 로그는 `disc0:/PSP_GAME/SYSDIR/EBOOT.BIN`을 실제 실행 경로로 사용한다. `BOOT.BIN`만 교체하면 BOOT UI 74개 번역이 화면에 도달하지 않으므로 두 경로를 함께 패치한다.
- 생성된 평문 ELF `1,128,036` bytes는 원본 EBOOT 슬롯 `1,128,384` bytes보다 348 bytes 작다. ELF 끝을 0으로 패딩해 ISO9660 레코드 크기와 extent를 유지한다.
- 패딩된 EBOOT SHA-256은 `2c515cda59931eb072b4621d435914a37413957c1df2f21741fa41275f2eb128`이며 PPSSPP Headless에서 모듈 시작과 게임 루프 진입을 확인했다.
- 이 결정은 PPSSPP 테스트용이다. 물리 PSP/정식 서명 환경 호환성은 별도 검증 전까지 보장하지 않는다.

- 기존 ASM은 공용 렌더러의 모든 2바이트 글자를 13px에서 9px로 줄여 일본어
  UI의 원래 갱신·클리어 형상과 불일치했다.
- 남은 코드 동굴 32바이트에 분기 helper를 넣어 한글 할당 lead `F0-F9`만
  9px, 원본 일본어는 13px를 사용한다.
- 대사 타자 효과와 ASCII 문장부호 패치는 유지한다. 스테이지를 반복 전환한
  실기 회귀 전까지 누적 손상 게이트는 PENDING이다.

# DEC-148 — record 87 교체는 네이티브 삽입 전후 content hash를 모두 지원

- 날짜: 2026-07-26
- 사용자 번역 PNG는 실제 네이티브 record 87에 삽입되지만, 삽입 결과의 indexed
  content hash는 기존 런타임 번역본 `f4cbdbb1`과 다른 `6ceb80dc`다.
- PPSSPP exact replacement는 전체 키가 일치해야 하므로 주소·CLUT가 같아도
  과거 해시 파일만으로는 현재 직접 실행본에 적용되지 않는다.
- 생성기는 두 content hash의 CLUT 3종을 모두 입력으로 요구하고 총 6개 exact
  파일을 설치한다. 이후 새 지원 빌드에서 또 다른 해시가 관측되면 덤프와
  소비 경로를 확인한 뒤 명시적으로 목록에 추가한다.
- 동적 텍스트의 임의 내용 해시 확장 금지 정책은 유지한다. 이번 예외는 고정
  record 87의 네이티브 삽입 전후 identity 두 개에만 적용한다.
