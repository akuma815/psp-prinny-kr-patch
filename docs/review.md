# 최종 번역 검토 큐

## Demo00 화자명 길이 검토

2026-07-22 실제 PPSSPP 화면에서 화자 말풍선 폭이 원문의 `speaker_box_style` 값에 따라 고정되고, 한글 화자명이 원문보다 길면 말풍선 밖으로 넘어가는 현상을 확인했다. 이에 따라 공백과 문장부호를 포함한 유니코드 글자 수가 원문 화자명보다 긴 번역을 별도 검토 대상으로 관리한다. 이 기준은 안전한 축약 후보를 찾기 위한 보수적 판정이며, 실제 글리프 폭 검증을 대체하지 않는다.

- 원장: `workspace/text/demo00_translation.json`
- 편집 목록: `workspace/text/demo00_speaker_length_review.json`
- 열람 목록: `workspace/text/demo00_speaker_length_review.md`
- 생성·반영 도구: `workspace/scripts/demo00_speaker_length_review.py`
- 현재 집계: 영향 엔트리 139개, 중복을 묶은 수정 항목 14개
- 사용자가 수정할 필드: 각 항목의 `replacement_speaker`
- 현재 상태: 목록만 생성했으며 번역 원장에는 아직 반영하지 않음

목록을 다시 생성할 때는 다음 명령을 사용한다.

```powershell
python .\workspace\scripts\demo00_speaker_length_review.py generate `
  .\workspace\text\demo00_translation.json `
  .\workspace\text\demo00_speaker_length_review.json `
  .\workspace\text\demo00_speaker_length_review.md
```

사용자 수정이 끝난 뒤에는 `apply` 모드가 각 `entry_id`의 원문 화자와 현재 번역 스냅샷을 다시 대조하고, 교체 화자명이 원문 길이를 넘지 않는지 확인한 다음 `translation.speaker`만 일괄 변경한다. `protected` 필드가 달라지면 적용을 중단한다. 일반 대사의 넓은 공백 간격은 화자명 축약과 별개의 글리프 advance 문제이므로 후속 엔진 검토 항목으로 유지한다.

## 목적

Demo00의 남은 번역을 먼저 전량 초벌한 뒤 검토가 필요한 항목을 한 번에 처리한다. 장면 배치마다 사용자 승인을 요청하지 않는다. 현행 번역 원장은 `workspace/text/demo00_translation.json`, 파생 검토 큐는 `work/analysis/demo00_review_queue.json`이다.

## 상태 정책

| 상태 | 의미 | 중간 단계 처리 | 최종 단계 처리 |
| --- | --- | --- | --- |
| `untranslated` | 아직 역문이 없음 | 계속 번역 | 0건이어야 검토 시작 |
| `needs_review` | 일반 초벌, 교차검토 필요 | 큐에 누적 | 원문·문맥·용어·조판 재검토 |
| `needs_human_review` | 용어·의역·문체 등 사람 판단 필요 | 큐에 누적 | 선택지와 근거를 모아 사용자 일괄 승인 |
| `complete` | 기존 승인 완료 또는 최종 검토 통과 | 유지 | 결함 발견 시 해당 검토 상태로 강등 |

새 초벌은 사용자 판단이 없어도 되는 항목을 `needs_review`, 의미 선택이 필요한 항목을 `needs_human_review`로 기록한다. 전체 초벌이 끝나기 전에는 새 항목을 `complete`로 승격하지 않는다.

## 중간 체크포인트

매번 유지하는 검사는 원본 보호 스냅샷 충돌, 안정 ID 충돌, 화자 16바이트·본문 34바이트 예상 슬롯 초과다. 실패 항목은 번역 진행과 별도로 즉시 격리한다. 전체 207,520바이트 왕복, 전체 회귀 테스트, 생산 인코딩·글리프 커버리지, PPSSPP 화면 검증은 전체 초벌 완료 뒤 최종 검토 라운드에서 수행한다. 포맷이나 도구 코드가 바뀐 경우에는 영향 범위에 맞는 테스트만 중간에 실행한다.

## 큐 생성

```powershell
python .\workspace\scripts\demo00_review_queue.py `
  .\workspace\text\demo00_translation.json `
  .\workspace\text\batches `
  .\work\analysis\demo00_review_queue.json
```

큐는 SSOT에서 파생하므로 직접 편집하지 않는다. `review_id`, 안정 `entry_id`, 물리 좌표, 원문, 역문, 플래그와 해당 배치의 장면·실행 근거를 함께 제공한다.

## 최종 검토 순서

1. `untranslated=0`과 번역 대상 분모를 확인한다.
2. `needs_review`를 장면 순서로 교차검토한다.
3. `needs_human_review`의 선택지·근거를 묶어 사용자에게 일괄 제시한다.
4. 수정 결과로 고유 글리프 수요와 예상 슬롯을 다시 계산한다.
5. 보호 필드 대조와 원문 왕복, 전체 회귀 테스트를 실행한다.
6. 생산용 인코딩과 실제 PPSSPP 화면 조판을 검증한 항목만 `complete`로 승격한다.
